Operating Systems & Kernel Concepts

Day 15 Processes: fork, exec, States & subprocess

15.1 What is a Process?

A process is an isolated executing instance of a program managed by the OS kernel (PCB - Process Control Block). Each process owns a unique PID, isolated virtual address space, file descriptor table, environment variables, and CPU register state.

15.2 fork() & Copy-on-Write (COW)

fork() clones the calling process. It returns the child PID to the parent and 0 to the child.

import os

pid = os.fork()
if pid == 0:
    print(f"Child Process: PID={os.getpid()}, Parent PID={os.getppid()}")
    os._exit(0)
else:
    print(f"Parent Process: Spawned child {pid}")
    os.wait()  # Wait for child to exit to prevent zombie state!

Copy-on-Write (COW): Modern OS kernels share physical memory pages (read-only) between parent and child until either process writes to a page. Only then is that specific 4 KB page duplicated, making fork() fast and memory efficient.

15.3 exec() & Process Image Replacement

The exec() family replaces the current process image (code, heap, stack) with a new binary, while keeping the existing PID and open file descriptors intact.

15.4 Process State Machine

READY ---(Scheduler Assigns CPU)---> RUNNING RUNNING --(Time Slice Expired)-----> READY RUNNING --(Wait for I/O / Lock)----> BLOCKED BLOCKED --(I/O Complete / Signal)---> READY RUNNING --(calls exit())-----------> ZOMBIE ZOMBIE --(parent calls wait())----> GONE

15.5 Environment Variables & subprocess

import subprocess

# Safe subprocess execution with pipe communication
proc = subprocess.Popen(
    ['python3', '-c', 'print("Hello from child")'],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True
)
stdout, stderr = proc.communicate(timeout=5)
print(stdout.strip())
Day 16 Threads, Locks, Semaphores & Deadlocks

16.1 Threads vs Processes

Threads share the same virtual address space (heap, global variables, open FDs) within a process, but have their own execution stack, CPU registers, and thread ID.

16.2 CPython GIL Mechanics

CPython enforces a Global Interpreter Lock (GIL) ensuring only one thread executes Python bytecode at a time. The GIL is released during I/O operations and long-running C extensions (e.g. NumPy), enabling thread parallelization for I/O-bound tasks but NOT CPU-bound tasks.

16.3 Synchronization Primitives

import threading, queue

lock = threading.Lock()
rlock = threading.RLock()        # Reentrant lock — same thread can acquire multiple times
semaphore = threading.Semaphore(3)  # Allows max 3 concurrent threads
event = threading.Event()        # Flag signaling between threads
condition = threading.Condition(lock)  # Wait for a predicate to become true

# Thread-safe queue for worker communication
task_queue = queue.Queue(maxsize=100)

# Thread-local storage — each thread gets its own copy
thread_local = threading.local()

def worker():
    thread_local.request_id = "req-" + str(threading.get_ident())
    # Each thread has independent thread_local.request_id
    print(thread_local.request_id)

16.4 Deadlocks & Coffman Conditions

A deadlock occurs when two or more threads are blocked forever, each holding a lock the other requires. The 4 Coffman conditions for deadlock:

  1. Mutual Exclusion: Resource cannot be shared.
  2. Hold and Wait: Holding a resource while waiting for another.
  3. No Preemption: Locks released only voluntarily.
  4. Circular Wait: A circular chain of dependent waiting threads.

Prevention: Always enforce strict Lock Ordering across all threads!

16.5 GIL Release Points

CPython's GIL is released during:

  • I/O system calls (socket read/write, file read/write)
  • Long-running C extensions (NumPy matrix operations, hashlib)
  • Every 5ms (sys.getswitchinterval()) to allow other threads to run
  • time.sleep() — always releases GIL
import sys
sys.getswitchinterval()   # Returns 0.005 (5ms default)
sys.setswitchinterval(0.001)  # More frequent thread switching (I/O-heavy workloads)
Day 17 Virtual Memory, Paging, Page Faults & Address Space Layout

17.1 Virtual Memory & Page Tables

The MMU (Memory Management Unit) translates 64-bit virtual memory addresses to physical RAM frames using page tables. The TLB (Translation Lookaside Buffer) acts as a hardware L1 cache for address translations.

17.2 Page Faults

  • Minor Page Fault: Requested page is in memory but not mapped (e.g., initial allocation or Copy-on-Write page hit). Handled fast in RAM.
  • Major Page Fault: Page must be fetched from disk swap space. Causes severe ms-level latency!

17.3 64-Bit Linux Process Address Space Layout

0x0000000000000000 ┌─────────────────────────────────┐ │ Unmapped / Guard Page │ ├─────────────────────────────────┤ │ Text Segment (Code, Read-Only) │ ├─────────────────────────────────┤ │ Data & BSS Segments (Globals) │ ├─────────────────────────────────┤ │ Heap (grows upward ↑) │ │ ... │ │ Shared Libraries (mmap) │ │ ... │ │ Stack (grows downward ↓) │ ├─────────────────────────────────┤ │ Kernel Space (Protected) │ 0xFFFF800000000000 └─────────────────────────────────┘

17.4 Memory-Mapped Files (mmap)

import mmap

with open("data.bin", "r+b") as f:
    mm = mmap.mmap(f.fileno(), 0)
    print(mm[:10])  # Zero-copy memory access directly from OS page cache!
    mm.close()
Day 18 File Systems, File Descriptors, Buffering & epoll

18.1 File Descriptors & Syscalls

File descriptors are non-negative integers assigned by the kernel (0=stdin, 1=stdout, 2=stderr). System calls (open, read, write, close) trigger a CPU privilege mode switch from User Mode to Kernel Mode.

18.2 Buffering & Page Cache

Write Path: Python Code -> Python User Buffer (f.flush()) -> OS Page Cache (os.fsync()) -> Disk Controller Queue -> NVMe/SSD

18.3 Non-Blocking I/O & epoll Multiplexing

Instead of spawning one thread per socket, epoll (Linux) enables monitoring millions of open file descriptors in $O(1)$ event time. This forms the foundation of CPython's asyncio event loop!

Day 19 Signals, Zombie Processes & Graceful Shutdown

19.1 POSIX Signals

  • SIGTERM (15): Standard request for graceful application termination.
  • SIGKILL (9): Immediate uncatchable kill by kernel.
  • SIGINT (2): Keyboard interrupt (Ctrl+C).
  • SIGCHLD (17): Emitted when a child process terminates or stops.

19.2 Zombie & Orphan Processes

A Zombie is a terminated process whose parent has not yet invoked wait() to read its exit status code. An Orphan is a running process whose parent died; it is automatically adopted by init (PID 1) or a system subreaper.

19.3 Production Graceful Shutdown Pattern

import signal, sys, time, threading

shutdown_event = threading.Event()

def signal_handler(signum, frame):
    print(f"\nCaught signal {signum}. Initiating graceful shutdown...")
    shutdown_event.set()

signal.signal(signal.SIGTERM, signal_handler)
signal.signal(signal.SIGINT, signal_handler)

# Worker loop checking shutdown_event
def worker():
    while not shutdown_event.is_set():
        time.sleep(0.5)

t = threading.Thread(target=worker)
t.start()
shutdown_event.wait()  # Block main thread until signal received
t.join(timeout=5)
print("Clean shutdown complete.")

20.2 Combining asyncio with ProcessPoolExecutor

import asyncio
from concurrent.futures import ProcessPoolExecutor

def cpu_heavy_calculation(data):
    return sum(i * i for i in range(data))

async def main():
    loop = asyncio.get_running_loop()
    with ProcessPoolExecutor() as pool:
        # Offload CPU work from event loop to process pool
        result = await loop.run_in_executor(pool, cpu_heavy_calculation, 10_000_000)
        print(f"Result: {result}")

Day 21 Review & Concurrency Benchmarks

21.1 Benchmark Findings

I/O Benchmark (100 network calls): Serial : ~10,000 ms Threading : ~500 ms Asyncio : ~120 ms (Highest throughput!) CPU Benchmark (8 heavy math tasks on 4 cores): Serial : ~8,000 ms Threading : ~8,100 ms (GIL slowdown due to lock contention!) Multiprocess : ~2,100 ms (True 4-core scaling!)

21.2 Week 3 Interview Q&A

Q: What is Copy-on-Write (COW) and how does it optimize fork()?
A: Copy-on-Write marks parent memory pages as read-only and shares them with the child process upon fork(). Memory pages are only duplicated when a process attempts to write to them, making process creation fast and memory-efficient.
Q: Why does CPython use the GIL and when is it released?
A: The GIL simplifies memory management by protecting reference count updates from race conditions. It is released during I/O system calls, long-running C extensions (like NumPy), or every 5ms during bytecode execution.
Q: Why is epoll superior to select for high-concurrency servers?
A: select() scans the entire file descriptor array in $O(N)$ time on every call and is capped at 1024 descriptors. epoll uses an in-kernel red-black tree and event list to notify active sockets in $O(1)$ time, scaling to millions of connections.
