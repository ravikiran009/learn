22.2 Spatial Locality & 64-Byte Cache Lines

Memory is fetched from RAM into CPU caches in fixed 64-byte Cache Lines. Accessing contiguous sequential memory arrays takes full advantage of spatial locality!

# Cache-Friendly: Row-Major Traversal (Contiguous memory access)
for i in range(N):
    for j in range(N):
        matrix[i][j] += 1

# Cache-Unfriendly: Column-Major Traversal (Strided memory jumps across cache lines)
for j in range(N):
    for i in range(N):
        matrix[i][j] += 1
Day 23 Instruction Pipelines, Branch Prediction & Assembly

23.1 5-Stage CPU Instruction Pipeline

IF (Fetch) -> ID (Decode) -> EX (Execute) -> MEM (Memory Access) -> WB (Write Back)

Pipeline Hazards: Data hazards (dependency on incomplete prior instruction), Control hazards (branch misprediction requiring pipeline flush costing 15–20 cycles), and Structural hazards (hardware resource conflicts).

23.2 x86-64 Register Set & System V AMD64 ABI

  • rax: Return value & general accumulator
  • rsp: Current stack pointer top address
  • rbp: Base stack frame pointer
  • rip: Instruction pointer (Program Counter)
  • rdi, rsi, rdx, rcx, r8, r9: System V ABI function call argument registers (Linux/macOS)
Day 24 OSI Model, TCP/IP, Sockets, DNS & HTTP

24.1 TCP 3-Way Handshake & 4-Way Teardown

Connection Setup (3-Way Handshake): Client --[ SYN (seq=x) ]-------------> Server Client <--[ SYN-ACK (seq=y, ack=x+1) ]-- Server Client --[ ACK (ack=y+1) ]------------> Server Connection Teardown (4-Way FIN): Client --[ FIN ]--> Server --[ ACK ]--> Client Server --[ FIN ]--> Client --[ ACK ]--> Client (Enters TIME_WAIT state for 2*MSL)

Day 25 HTTP/2, HTTP/3, QUIC, WebSockets & gRPC

25.1 Evolution of HTTP Protocols

  • HTTP/1.1: Text-based, persistent keep-alive connections, prone to Head-of-Line (HOL) blocking at application level.
  • HTTP/2: Binary framing layer, HPACK header compression, full bidirectional multiplexing over single TCP connection.
  • HTTP/3 (QUIC): Built on UDP. Eliminates TCP-level HOL blocking, supports 0-RTT connection resumption, and provides seamless WiFi-to-Cellular connection migration.

25.2 gRPC & Protocol Buffers

gRPC utilizes Protocol Buffers (compact binary serialization) over HTTP/2 multiplexed streams, supporting Unary, Server Streaming, Client Streaming, and Bidirectional Streaming RPCs.

Day 26 Reverse Proxies, Load Balancing & Connection Pools

26.1 Load Balancing Algorithms

  • Round Robin: Sequential rotation (assumes equal server capacity).
  • Least Connections: Routes traffic to instance with fewest active connections.
  • Consistent Hashing / IP Hash: Maps client IPs onto hash ring for sticky session affinity.
  • Power of Two Random Choices: Picks 2 random nodes and routes to the less loaded one.

26.2 Exponential Backoff with Full Jitter

import time, random

def execute_with_retry(operation_func, max_attempts=5, base_delay=1.0):
    for attempt in range(max_attempts):
        try:
            return operation_func()
        except Exception as e:
            if attempt == max_attempts - 1: raise
            # Exponential backoff with random full jitter to prevent thundering herds
            sleep_time = random.uniform(0, base_delay * (2 ** attempt))
            time.sleep(sleep_time)
Day 27 TLS 1.3 Security, Certificate Chains & Resumption

27.1 TLS 1.3 1-RTT Handshake Flow

Client Server │ ────── ClientHello + Key Share (Diffie-Hellman) ────> │ │ <───── ServerHello + Cert + Encrypted Extensions ──── │ │ ────── Finished (Encrypted Data Starts!) ──────────> │

TLS 1.3 encrypts certificate exchange and cuts handshake latency down from 2 RTTs (in TLS 1.2) to just 1 RTT.

Day 28 End-to-End Request Trace

Tracing a single browser request (e.g. https://api.example.com/checkout):

  1. DNS Lookup: Browser Cache → OS Cache → Resolver → Root/TLD/Auth Nameserver (returns IPv4 A record).
  2. TCP & TLS 1.3 Handshake: SYN/SYN-ACK/ACK + ECDHE key exchange (1 RTT).
  3. Reverse Proxy Gateway: Nginx/Envoy terminates TLS, applies Rate Limiting (Token Bucket), routes via Least Connections to backend pod.
  4. Application Server: Python asyncio event loop reads socket via epoll, fetches connection from SQLAlchemy pool, executes query, and streams JSON response.
