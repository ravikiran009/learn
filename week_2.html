Day 8 Reference Cycles, Generational GC & Weak References

8.1 Reference Cycles — Why They Matter

A reference cycle occurs when a chain of objects references back to itself. Reference counting alone cannot collect cycles because ob_refcnt never drops to zero.

# 1. Self-referential object
lst = []
lst.append(lst)   # lst.refcount = 2; del lst -> refcount = 1 (leaked!)

# 2. Mutual reference
class Node:
    def __init__(self, val): 
        self.val = val
        self.child = None

a = Node(1); b = Node(2)
a.child = b; b.child = a   # Reference cycle!

# 3. Function closures creating cycles
def make():
    x = []
    def inner(): return x   # inner holds reference to x via closure cell
    x.append(inner)         # x holds reference to inner -> cycle

To detect leaking cycles during testing:

import gc
gc.set_debug(gc.DEBUG_LEAK)
gc.collect()   # force collection and print leaked objects

8.2 Generational Garbage Collection

Python's cyclic GC divides all tracked container objects into 3 generations based on age:

  • Gen 0: Newly allocated objects (default allocation threshold: 700)
  • Gen 1: Survived at least 1 Gen 0 collection sweep (threshold: 10)
  • Gen 2: Long-lived objects (threshold: 10)

Simplified Mark-and-Sweep Algorithm:

  1. For each object in the set being collected, copy ob_refcnt into gc_refs.
  2. For every object, subtract 1 from gc_refs for each pointer it holds to another object in the candidate set.
  3. If an object's gc_refs hits 0, it is tentatively marked as candidate garbage.
  4. If an object in the candidate set is reachable from outside the candidate set (its gc_refs > 0), promote it and resurrect all objects reachable from it.
  5. Finalize and deallocate confirmed garbage objects.
import gc
print(gc.get_threshold())      # (700, 10, 10)
print(gc.get_count())          # current (count0, count1, count2)
gc.collect(generation=2)        # force full collection of all generations

8.3 Weak References & Finalizers

A weak reference (weakref.ref) allows accessing an object without incrementing its ob_refcnt. When the target object is collected, the weak reference evaluates to None.

import weakref

class CacheObject:
    def __init__(self, name): self.name = name

obj = CacheObject("data")
ref = weakref.ref(obj)

print(ref())   # 
del obj
print(ref())   # None (object was garbage collected!)

# Weak reference dictionaries:
cache = weakref.WeakValueDictionary()
cache['key'] = CacheObject("expensive")  # collected automatically when no other strong refs exist

# Safe cleanup callback with weakref.finalize:
def cleanup(name):
    print(f"Cleaned up resource {name}")

target = CacheObject("db_conn")
weakref.finalize(target, cleanup, target.name)
del target    # Triggers cleanup("db_conn") without reference cycle!
Day 9 Descriptors, __get__, Properties & Attribute Lookup Order

9.1 The Descriptor Protocol

A descriptor is an object that controls attribute access by defining one or more of __get__, __set__, or __delete__.

  • Non-Data Descriptor: Defines only __get__ (e.g. standard Python functions/methods).
  • Data Descriptor: Defines __get__ AND __set__ (or __delete__) (e.g. property).

9.2 Complete Attribute Lookup Order

When you evaluate obj.attr, Python evaluates attributes in strict priority:

  1. Search type(obj).__mro__ for a Data Descriptor matching attr. If found, call its __get__.
  2. Check instance dictionary obj.__dict__['attr']. If found, return value.
  3. Search type(obj).__mro__ for a Non-Data Descriptor or class attribute. If a non-data descriptor is found, call its __get__.
  4. If __getattr__ is defined on the class, call obj.__getattr__('attr') as fallback.
  5. Otherwise, raise AttributeError.
CRITICAL RULE: Data Descriptors OVERRIDE Instance __dict__! Instance __dict__ OVERRIDES Non-Data Descriptors!
class DataDesc:
    def __get__(self, obj, typ=None): return "DataDesc WINS"
    def __set__(self, obj, val): pass  # Makes it a data descriptor!

class NonDataDesc:
    def __get__(self, obj, typ=None): return "NonDataDesc"

class Example:
    d = DataDesc()
    nd = NonDataDesc()

e = Example()
e.__dict__['d'] = "Instance Val"
e.__dict__['nd'] = "Instance Val"

print(e.d)   # "DataDesc WINS" (Data descriptor beats __dict__)
print(e.nd)  # "Instance Val" (Instance __dict__ beats non-data descriptor)

9.3 Properties & Custom Descriptor Validation

class ValidatedPositive:
    def __set_name__(self, owner, name):
        self.name = name   # Auto-captures variable name at class creation!

    def __get__(self, instance, owner):
        if instance is None: return self
        return instance.__dict__.get(self.name, 0)

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError(f"{self.name} must be positive!")
        instance.__dict__[self.name] = value

class Product:
    price = ValidatedPositive()
    quantity = ValidatedPositive()

p = Product()
p.price = 100     # OK
# p.price = -10   # Raises ValueError: price must be positive!

9.4 Functions are Descriptors

In Python, regular functions are non-data descriptors! Accessing a function from an instance calls its __get__(instance, class), which returns a PyMethodObject (bound method) that automatically passes self as the first argument!

Day 10 Classes, Dataclasses, __slots__ & Memory Tradeoffs

10.1 Class Creation & Instance __dict__ Overhead

By default, every Python instance allocates an instance __dict__ to store dynamic attributes. A standard empty class instance consumes ~232 bytes due to dictionary hash table overhead.

10.2 __slots__ Optimization

__slots__ instructs CPython to allocate a fixed-size C array of pointers instead of a dynamic __dict__, saving 3–4x memory per instance.

class PointSlots:
    __slots__ = ('x', 'y')
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = PointSlots(10, 20)
# p.__dict__  -> AttributeError!
# p.z = 30    -> AttributeError! (Prevents adding undeclared attributes)

10.3 Dataclasses (Python 3.7+) & slots=True

from dataclasses import dataclass, field

@dataclass(slots=True, frozen=True)
class Coordinate:
    latitude: float
    longitude: float
    metadata: list = field(default_factory=list, repr=False, compare=False)

Day 11 Metaclasses, Class Creation, __new__ & __init_subclass__

11.1 What is a Metaclass?

A metaclass is a class whose instances are classes. In Python, type is the default metaclass of all classes. Class creation flow:

1. Metaclass __prepare__(name, bases) -> returns namespace dictionary 2. Execute class body inside namespace dictionary 3. Metaclass __new__(mcs, name, bases, namespace) -> allocates PyTypeObject 4. Metaclass __init__(cls, name, bases, namespace) -> initializes class

11.2 Metaclass Enforcement & Singleton Pattern

class StrictMeta(type):
    def __new__(mcs, name, bases, namespace):
        for key, val in namespace.items():
            if callable(val) and not key.startswith("__") and not val.__doc__:
                raise TypeError(f"Method '{name}.{key}' must have a docstring!")
        return super().__new__(mcs, name, bases, namespace)

class SingletonMeta(type):
    _instances = {}
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class DatabaseConnection(metaclass=SingletonMeta):
    def __init__(self): self.connected = True

db1 = DatabaseConnection()
db2 = DatabaseConnection()
print(db1 is db2)  # True

11.3 __new__ vs __init__ & __init_subclass__

# __new__ creates the instance; __init__ initializes it
class PositiveInt(int):
    def __new__(cls, value):
        if value <= 0: raise ValueError("Must be positive")
        return super().__new__(cls, value)

# __init_subclass__ as a clean plugin registration pattern (no metaclass required!)
class PluginBase:
    registry = {}
    def __init_subclass__(cls, plugin_type=None, **kwargs):
        super().__init_subclass__(**kwargs)
        if plugin_type:
            cls.registry[plugin_type] = cls

class CSVPlugin(PluginBase, plugin_type="csv"): pass
class JSONPlugin(PluginBase, plugin_type="json"): pass
print(PluginBase.registry)  # {'csv': , 'json': }
Day 12 Import System, Module Loading, Circular Imports & importlib

12.1 How Import Works

Executing import foo follows this pipeline:

  1. Check sys.modules['foo'] (cached module table). If hit, return immediately.
  2. Iterate over finders in sys.meta_path (e.g. BuiltinImporter, PathFinder) to get a module spec.
  3. Call loader from spec to create the module object and insert it into sys.modules.
  4. Execute the module bytecode inside the module's namespace.
  5. Bind module variable in importing scope.

12.2 Circular Imports & Solutions

Circular imports occur when a.py imports b.py while b.py imports a.py. Because sys.modules holds a partial module object before code execution completes, accessing unexecuted names causes an ImportError.

  • Solution 1: Refactor shared dependencies into a separate module (e.g. common.py).
  • Solution 2: Deferred import — move import inside function bodies.
  • Solution 3: Import the module object (import a) instead of importing names directly (from a import foo).

12.3 Programmatic Imports with importlib

import importlib

# Dynamic module loading:
math_mod = importlib.import_module("math")
print(math_mod.sqrt(16))  # 4.0

# Module reloading:
importlib.reload(math_mod)

13.2 Reflection & Dynamic Dispatch

class RequestHandler:
    def handle_get(self): return "Handling GET"
    def handle_post(self): return "Handling POST"

handler = RequestHandler()
method_name = f"handle_{'get'.lower()}"
method = getattr(handler, method_name, None)
if callable(method):
    print(method())   # "Handling GET"

13.3 Monkey Patching & unittest.mock

import json
original_dumps = json.dumps

# Monkey patch json.dumps to default indent=2
def pretty_dumps(*args, **kwargs):
    kwargs.setdefault('indent', 2)
    return original_dumps(*args, **kwargs)

json.dumps = pretty_dumps
print(json.dumps({"a": 1}))  # Formatted with indent=2!
json.dumps = original_dumps   # Restore original!

13.4 __getattr__ vs __getattribute__

  • __getattr__(self, name): Fallback hook. Called only when name is NOT found in __dict__ or class hierarchy.
  • __getattribute__(self, name): Called for every single attribute access. Must use super().__getattribute__(name) to avoid infinite recursion!
Day 14 Review — Build an Introspection/Bytecode Inspection Tool

14.1 Project: Object Inspector Tool

import inspect, dis, sys

def inspect_object(obj):
    cls = type(obj)
    print("=" * 60)
    print(f"OBJECT INSPECTOR REPORT FOR: {obj}")
    print("=" * 60)
    print(f"Type        : {cls.__name__}")
    print(f"MRO         : {[c.__name__ for c in cls.__mro__]}")
    print(f"Memory Size : {sys.getsizeof(obj)} bytes")

    if hasattr(obj, '__slots__'):
        print(f"Slots       : {obj.__slots__}")
    elif hasattr(obj, '__dict__'):
        print(f"Instance Dict: {list(obj.__dict__.keys())}")

    if callable(obj):
        try:
            print(f"Signature   : {inspect.signature(obj)}")
        except ValueError:
            pass
        if hasattr(obj, '__closure__') and obj.__closure__:
            print("Closure Vars:")
            for cell, freevar in zip(obj.__closure__, obj.__code__.co_freevars):
                print(f"  {freevar} = {cell.cell_contents}")
        print("\n--- Bytecode Disassembly ---")
        dis.dis(obj)

# Test run:
def sample_closure(multiplier):
    def inner(val):
        return val * multiplier
    return inner

fn = sample_closure(5)
inspect_object(fn)

14.2 Week 2 Interview Q&A

Q: How does Python's attribute lookup order work with descriptors?
A: Python checks in order: (1) Data Descriptors in class MRO, (2) Instance __dict__, (3) Non-Data Descriptors and class attributes in MRO, (4) __getattr__ fallback.
Q: When would you use __slots__ over standard classes?
A: When instantiating millions of small objects (like ORM rows, geometric vectors, or network packets) where the __dict__ memory overhead would cause performance degradation or OOM issues.
Q: What is the difference between __new__ and __init__?
A: __new__ is the static constructor that allocates and returns the object instance in memory. __init__ is the initializer that sets instance attributes. Subclassing immutable types (like int, str, tuple) requires overriding __new__.
