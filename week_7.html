Day 43 REST API Design: Versioning, Pagination, Idempotency & Status Codes

43.1 Cursor Pagination vs Offset Pagination

Offset pagination (LIMIT 10 OFFSET 50) degrades to $O(N)$ scanning on large tables and suffers from item shifting when rows are inserted concurrently. Cursor Pagination uses a base64-encoded pointer (e.g. id > 100 ORDER BY id LIMIT 10) for stable $O(1)$ index lookups!

Day 44 Authentication & Authorization: JWT, OAuth2, PKCE & RBAC

44.1 JWT Anatomy & Security Best Practices

JWT Format: header.payload.signature (Base64URL encoded) Header: {"alg": "HS256", "typ": "JWT"} Payload: {"sub": "usr_123", "exp": 1700000000, "role": "admin"} Signature: HMAC-SHA256(Base64(Header) + "." + Base64(Payload), SecretKey)

Security Rule: Never store JWT tokens in localStorage (vulnerable to XSS). Always store access tokens in httpOnly; Secure; SameSite=Strict cookies!

44.2 OAuth 2.0 PKCE Flow (Proof Key for Code Exchange)

Public clients (SPAs, mobile apps) generate a random code_verifier and send code_challenge = SHA256(code_verifier) during authorization to prevent auth code interception attacks.

Day 45 asyncio Internals: Coroutines, Tasks & TaskGroup

45.1 asyncio Execution Flow

import asyncio

async def fetch_data(service_id):
    await asyncio.sleep(0.1)
    return f"Response from service {service_id}"

async def main():
    # Python 3.11+ TaskGroup for safe exception propagation and automatic cleanup
    async with asyncio.TaskGroup() as tg:
        task1 = tg.create_task(fetch_data(1))
        task2 = tg.create_task(fetch_data(2))
    print(task1.result(), task2.result())

46.1 Celery Primitives

from celery import chain, group, chord

# Chain: Execute tasks sequentially
chain(task_a.s(), task_b.s(), task_c.s()).delay()

# Group: Execute tasks in parallel
group(task_worker.s(i) for i in range(10)).delay()

# Chord: Parallel execution followed by callback aggregation
chord(group(fetch.s(i) for i in range(5)), aggregate_results.s()).delay()
Day 47 Rate Limiting, Circuit Breakers & Bulkheads

47.1 Token Bucket Rate Limiting (Redis)

def is_rate_limited(user_id: str, limit: int = 100, window_sec: int = 60) -> bool:
    current_bucket = int(time.time() // window_sec)
    key = f"rate:{user_id}:{current_bucket}"
    req_count = redis_client.incr(key)
    if req_count == 1:
        redis_client.expire(key, window_sec)
    return req_count > limit

REQUEST_COUNT = Counter("http_requests_total", "Total HTTP Requests", ["method", "endpoint"])

Day 49 Production Service Architecture Review
Q: What is the difference between RabbitMQ and Apache Kafka?
A: RabbitMQ is a traditional message broker where messages are deleted upon consumer ACK (great for task queues and complex routing). Kafka is a distributed append-only log where events are retained on disk and replayable by multiple consumer groups (great for event streaming and high throughput).
